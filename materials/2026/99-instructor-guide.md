# 講師ガイド

このファイルは参加者向けではありません。メンター / 講師が進行と説明順を合わせるための内部資料です。

## 講座の狙い

初回講座では、Next.js の全機能を教えません。参加者がハッカソン中に自分で画面を足せるように、以下の感覚を持ってもらうことを優先します。

- データの形を決める
- 配列を画面に並べる
- 入力で状態を変える
- 状態から表示を作る
- URL ごとにページを分ける

去年の TypeScript 講座は文法中心、Next.js 講座はフレームワーク中心でした。今年版は、両方を `KCL Shop` の実装に接続して説明します。

今回は完成版を見せて写経させる形ではなく、`web` の TODO を順番に埋めていく進行です。講師は「今どの TODO を埋める時間か」を常に明示してください。

## 事前準備

講師側:

```bash
cd Lecture0-NextJs/web
npm install
npm run dev
```

ブラウザで `http://localhost:3000` を開き、以下を確認します。

- トップページが表示される
- 商品詳細ページへ移動できる
- カテゴリ選択が動く
- 検索欄に入力できる
- TODO と Phase コメントが講座順に並んでいる

投影用スライド:


## 説明の順番

### 1. スターター画面を先に見せる

「今日は TODO を埋めながら、一覧、検索、詳細というハッカソンでよく使う形を分解します」と伝えます。

### 2. TypeScript は安全装置として説明する

初心者には `string` や `number` の網羅よりも、「商品データに必ず `name` と `price` があると約束する」と説明します。

### 3. `map` は変換として説明する

`products` の配列が `ProductCard` の配列に変わる図を使います。`for` 文との違いに深入りしすぎないでください。

今年版では、`ProductList.tsx` の `products.map((_, index) => { ... })` を `products.map((product) => { ... })` に直すところから始めます。`product` が「配列の中の今見ている 1 件」であること、`index` は仮の key を保つために一時的に置いてあるだけであることを明示してください。

### 4. props は部品への入力として説明する

「同じカードの見た目を使い、渡す商品だけ変える」と説明します。数学の関数に慣れている人には `F(x)` の例を出してもよいです。

### 5. state は画面の記憶として説明する

`useState` は「今の検索文字」「今選んでいるカテゴリ」など、画面が覚える値です。

### 6. `useEffect` は後回しでもよい

初心者が多い場合、`useEffect` は「状態が変わった後に追加処理する場所」とだけ説明し、詳しい依存配列の話は発展に回します。

ただし今年版では、検索機能の核として `useEffect` を実際に書かせます。`filterProducts(products, searchTerm, selectedCategory)` を呼び、その結果を `setFilteredProducts(...)` に渡すところまでは本編で扱ってください。

この形は、`useEffect` の役割を見せるための教材上の設計です。実務では、検索結果のような派生データを state に入れず、render 中に計算する設計もあります。初回講座では深入りせず、「今回は `useEffect` の使いどころを体験するためにこの形にしている」と補足してください。

## 詰まりどころ

`"use client"` を忘れる:

- `useState`, `useEffect`, `localStorage`, `document.title` を使うファイルに必要
- Server Component と Client Component の厳密な説明は深追いしない

`map` の `{}` と `()` が混ざる:

- まずは完成版を写してよい
- `return` が必要な形と不要な形を並べて見せる
- `key={product.id}` と `product={product}` をセットで確認する

`TODO` の置換対象が分からない:

- 「いま書き換えるのは空文字か 0 だけ」と明示する
- 一度に複数ファイルへ飛ばさず、Phase ごとに対象ファイルを固定する

`useState` と `useEffect` の役割が混ざる:

- `useState` は値を覚える
- `useEffect` は値が変わったあとに処理する
- 検索機能では「入力値を覚える」のが `useState`、「その値から表示結果を作る」のが `useEffect`

`props` の型エラー:

- 親から渡している名前と、子の `Props` の名前が一致しているか確認する
- `onAddToCart` の引数が `string` か確認する

画像が表示されない:

- URL が正しいか確認する
- 今回は初心者向けのため `next/image` ではなく通常の `img` を使っていると説明する

`localStorage is not defined`:

- ブラウザだけの機能なので、`useEffect` の中で使う
- 初回講座では「サーバー側で動く時間もある」とだけ説明する

検索が動かない:

- `productFilters.ts` の `includes("")` が残っていないか確認する
- `page.tsx` の `filterProducts(products, searchTerm, selectedCategory)` を確認する
- ブラウザで入力を消してからもう一度検索する

詳細ページが期待通りに出ない:

- 商品カードのリンクが `/products/${product.id}` になっているか確認する
- `products.ts` の `id` が重複していないか確認する
- `[id]/page.tsx` の在庫と評価の `0` が残っていないか確認する

## 中級者への投げ方

早く終わった人には、講師説明を止めずに `02-challenges.md` を渡します。メンター側は `03-challenge-answers.md` を見ながらサポートしてください。おすすめ順は以下です。

1. 商品の並び替え
2. 在庫ゼロ表示
3. お気に入りだけを見るフィルター
4. URL クエリで検索状態を共有
5. `localStorage` 読み込みの型チェックを強化

## 終了時のまとめ

最後は機能名ではなく、ハッカソンで使う画面パターンに置き換えます。

- 商品一覧 -> 作品一覧、イベント一覧、チーム一覧
- 商品詳細 -> 作品詳細、ユーザープロフィール
- カート -> 選択リスト、お気に入り、比較リスト
- 検索 -> タグ絞り込み、カテゴリ絞り込み

この変換ができれば、参加者はハッカソンで別テーマにも応用できます。
